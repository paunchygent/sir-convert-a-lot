PR-sized execution unit; may be linked to a story or standalone.

## Objective

Publish a compact onboarding map that names the current service/source lanes and
keeps them validator-checked or generated so the map does not become another
stale truth surface.

## PR Scope

- Add a compact onboarding map for:
  - production conversion core
  - DigiExam migration route
  - draft Exam.net authoring route
  - OCR benchmark lane
  - Qwen/sidecar research
- For each lane, list status, owning story/task/contract docs, primary source
  entrypoints, command surface, validation gate, and explicit out-of-scope
  boundary.
- Make the map generated by `docs-sync` or checked by a docs validator so stale
  links, missing owners, or unclassified lanes fail validation.
- Link the map from the generated docs doorway or an existing reference index
  without turning it into a second handoff file.
- Keep durable procedure in owning runbooks/rules; the map is for navigation,
  not a duplicate policy manual.

## Deliverables

- [ ] Compact service/source onboarding map.
- [ ] Generator or validator coverage for required lanes and links.
- [ ] Docs doorway/index links to the map.
- [ ] Close-out note explaining how future tasks update the map safely.

## Acceptance Criteria

- [ ] The map contains all five required lanes with status, owner docs,
  source-entrypoint, command, validation, and boundary fields.
- [ ] A missing lane, broken owner link, or broken entrypoint link fails a
  documented validation command.
- [ ] The draft Exam.net authoring route is clearly marked draft/not runtime
  implemented until its governed implementation task lands.
- [ ] Qwen/sidecar research is visible but not presented as production
  conversion core.
- [ ] `pdm run docs-sync`, `pdm run docs-validate`,
  `pdm run skills-validate`, `pdm run handoff-validate`, and
  `git diff --check` pass.
