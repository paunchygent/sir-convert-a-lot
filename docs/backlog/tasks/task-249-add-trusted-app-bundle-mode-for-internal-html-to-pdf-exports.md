PR-sized execution unit; may be linked to a story or standalone.

## Objective

Add an explicit internal trust mode for app-owned `html -> pdf` bundles so
controlled downstream renderers such as Klassrumskartan do not have to pass
through the same hardened fetcher semantics used for arbitrary uploaded HTML.

The goal is not to loosen the public route globally. The goal is to preserve
the current untrusted-upload contract while adding one distinct, internal-only
execution mode for renderer-owned HTML/CSS/resources that are generated by
trusted applications under our control.

This task exists because Hemma proof showed the exact current seam:

- plain WeasyPrint inside `sir_convert_a_lot_prod` embeds local PNG assets;
- the same container, same image, and same HTML lose the image only when
  rendered through
  `scripts/sir_convert_a_lot/infrastructure/weasyprint_html_to_pdf.py`;
- the failure is specific to the service wrapper path using the restricted
  fetcher contract, not to WeasyPrint generally and not to the
  Klassrumskartan renderer itself.

## PR Scope

- Extend the v2 job contract for PDF-producing HTML routes with an explicit
  trust selector, for example:
  - `conversion.input_trust_mode = "untrusted_upload" | "trusted_app_bundle"`
- Keep `untrusted_upload` as the default and preserve the current public
  behavior:
  - no network fetches;
  - no workdir escape;
  - deterministic missing/invalid local resource validation.
- Add `trusted_app_bundle` as an internal-only mode for app-generated
  HTML/CSS/resources:
  - bundle remains limited to uploaded HTML + extracted resources zip;
  - no network fetches;
  - no paths outside the extracted workdir;
  - no arbitrary caller filesystem access;
  - relative local resources must resolve the way plain WeasyPrint expects for
    app-owned bundles.
- Implement the new branch only for `html -> pdf` in the v2 execution path.
- Add contract-level request validation so the new mode is rejected unless the
  request comes through the explicit internal credential lane.
- Update converter contract docs to distinguish:
  - public untrusted HTML uploads;
  - trusted internal app bundles.

Out of scope:

- changing `html -> md` trust behavior;
- broadening public `html -> pdf` resource access;
- adding any network fetch support;
- introducing hidden caller heuristics instead of an explicit trust contract;
- app-side watermark/layout work in Skriptoteket.

- [ ] The public contract stays explicit: callers must opt into the trusted

  absolute-path resources still fail closed.

## Proposed API Contract

`conversion.input_trust_mode`:

- `untrusted_upload`
  - default when omitted;
  - for arbitrary HTML/CSS uploads;
  - uses current hardened local-resource validation and restricted fetch
    behavior.
- `trusted_app_bundle`
  - internal-only;
  - for application-owned render bundles such as Klassrumskartan;
  - still limited to extracted job workdir resources;
  - intended to preserve plain WeasyPrint relative asset resolution for
    bundled local files.

Trusted-mode authorization surface:

- use the normal `X-API-Key` header but require a distinct internal adapter key
  configured separately from the public key, for example
  `SIR_CONVERT_A_LOT_INTERNAL_API_KEY`;
- only requests authenticated with that internal key may set
  `conversion.input_trust_mode="trusted_app_bundle"`;
- requests using the public key with trusted mode must fail with a deterministic
  authorization/validation error.

Schema and contract files:

  - add a new enum for trust mode;
  - extend `ConversionSpecV2` with `input_trust_mode`;
  - keep default behavior identical to current callers by defaulting to
    `untrusted_upload`;

  - add spec-level invariants so the field is never legal on non-HTML or
    non-PDF routes.

  - bind trusted mode to one explicit internal adapter API key lane rather than
    hidden heuristics.
- `scripts/sir_convert_a_lot/interfaces/http_routes_jobs_v2.py`
  - thread the trust selector through create-job validation and persistence.
- `scripts/sir_convert_a_lot/infrastructure/runtime_config_v2.py`
  - add explicit config for the internal adapter API key lane if it does not
    already exist.
- `scripts/sir_convert_a_lot/infrastructure/runtime_engine_v2.py`
  - ensure idempotency fingerprinting remains deterministic when trust mode
    differs so trusted/untrusted requests cannot collide silently.
- `scripts/sir_convert_a_lot/interfaces/http_client_v2.py`
  - support the new field in typed client submissions so internal callers and

## Execution Plan

1. Add the typed trust-mode field to the v2 spec and request validation.
1. Add one explicit internal adapter API key lane for trusted bundles and fail
   closed for any trusted-mode request on the public lane.
1. Split `html -> pdf` execution in the WeasyPrint wrapper by trust mode.
1. Prove locally that:
   - untrusted mode still blocks external and escaping resources;
   - trusted mode preserves bundled local image rendering.
1. Extend the Hemma verifier with one trusted-bundle probe.
1. Extend the Hemma verifier with:
   - one public-lane rejection probe for trusted mode;
   - trusted-mode negative probes for external, traversal, and absolute-path
     resources.
1. Run the Hemma probe against host lane `127.0.0.1:28085`.
1. Update the converter/downstream/runbook docs only after the behavior is
   proven.

## Decision Notes

Internal authorization for `trusted_app_bundle` should be explicit and narrow.
This slice chooses one dedicated internal API key lane as the sole trusted
credential surface. It should not implement broad role-based trust inference,
origin-based guessing, or “same repo therefore trusted” shortcuts.

## Hemma Evidence To Require

Pre-fix seam proof:

1. Inside `sir_convert_a_lot_prod`, plain WeasyPrint renders an HTML file with
   a local PNG and the resulting PDF contains image objects.
1. Inside the same container, the service wrapper path drops the image for the
   same content.

Post-fix proof:

1. A direct internal `trusted_app_bundle` probe against Hemma host lane
   `127.0.0.1:28085` succeeds.
1. The returned PDF contains `/Subtype /Image`.
1. The rasterized page visibly shows the bundled image.
1. The same probe through `untrusted_upload` still enforces the hardened
   restrictions.
