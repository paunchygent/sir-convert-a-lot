Implementation slice with acceptance-driven scope.

## Objective

Define the authenticated product/API delivery boundary for DigiExam migration
before QTI generation or service exposure lands. Teachers will use a public,
authenticated Skriptoteket interface to upload a DigiExam `.dxe` file plus an
optional sanitized graded-result PDF, then receive downloadable or saved
Exam.net migration artifacts generated by Sir Convert.

This story makes the cross-product ownership explicit: Skriptoteket owns the
teacher UX and authenticated user-file persistence, while Sir Convert owns
conversion execution, artifact generation, artifact manifests, and fail-closed
target semantics.

## Scope

- Define the Sir Convert service API contract for DigiExam migration jobs:
  primary `.dxe` upload, optional sanitized graded-result PDF, optional parity
  evidence, idempotency, correlation, result polling, and artifact retrieval.
- Define the terminal artifact bundle shape returned to Skriptoteket:
  Exam.net-oriented PDF, QTI/native import package when implemented, IR and
  migration manifest, warnings, manual-follow-up report, and asset records.
- Define authenticated ownership semantics for user-originated Skriptoteket
  calls, including Gateway/InternalIdentityContextV1 expectations, job access,
  artifact retention, and save-to-user-files handoff.
- Keep Skriptoteket as a thin consumer: no parser, renderer, answer-key
  reconstruction, or target-format policy forks in the app layer.
- Sequence implementation behind the contract:
  - Task 278 defines the API/artifact ownership contract.
  - A later QTI task consumes IR v2 and emits QTI/native artifacts.
  - A later service task wires DigiExam migration into the v2 job runtime.
  - A later Skriptoteket task builds the authenticated UI/adapter and user-file
    persistence flow against the Sir Convert contract.
- Keep anonymous public conversion, browser automation into Exam.net, and
  direct Exam.net upload out of this story unless a later accepted decision
  explicitly adds them.

## Acceptance Criteria

- [x] A governed API/artifact contract names the DigiExam migration request
  shape, companion-file semantics, terminal bundle contents, content types,
  retention, and error/status codes.
- [x] The contract states that `.dxe` is the required structure source and that
  sanitized graded-result PDFs may enrich only correct machine-marked answers.
- [x] The contract preserves the existing privacy boundary: no wrong answers,
  free-text student answers, scores, identity markers, or student-performance
  history are retained from result PDFs.
- [x] The contract defines named downloadable artifacts so Skriptoteket can
  save them into authenticated user files without inspecting Sir Convert
  internals.
- [x] The contract defines how manual-follow-up and fail-closed warnings are
  surfaced to the teacher instead of silently degrading unsupported target
  shapes.
- [x] User-originated Skriptoteket calls are aligned with the internal adapter
  contract and InternalIdentityContextV1 authorization profile; direct anonymous
  access remains fail-closed unless separately governed.
- [x] QTI/native renderer and service exposure tasks are blocked until the
  artifact/API contract is accepted.

## Test Requirements

Task 278 defines these requirements for later implementation tasks. They are
not runtime tests in the docs-only contract gate.

- Contract tests must cover request validation for `.dxe`, optional sanitized
  result-PDF companion files, unsupported companions, and payload-size limits.
- API tests must cover authenticated job ownership, idempotency replay, result
  polling, terminal bundle metadata, and named artifact retrieval.
- Bundle tests must prove the manifest lists PDF, QTI, IR, manual-follow-up,
  and asset outputs with deterministic filenames, content types, sizes, and
  hashes.
- Privacy tests must prove forbidden result-PDF data is absent from API
  responses, manifests, and bundle artifacts.
- Adapter conformance tests must cover Skriptoteket as a thin consumer with
  correlation/idempotency behavior and no conversion-policy drift.

Task 282 is the Sir Convert runtime task that must satisfy these service-side
tests. HuleEdu `ST-01-07` owns the Gateway/auth-edge route that signs
`InternalIdentityContextV1` with `aud=sir-convert-a-lot` before Skriptoteket
product traffic reaches these routes.

## Done Definition

Story 44 is done when Sir Convert exposes a governed, authenticated DigiExam
migration API contract and artifact bundle shape that Skriptoteket can consume
as a public authenticated app workflow, with QTI/service/UI implementation
tasks sequenced behind that accepted contract.
